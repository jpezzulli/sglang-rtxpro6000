# Build

This is a native, non-Docker build for one SM120 GPU. The commands below are a
reconstruction from the installed environment, source metadata, retained NIXL
Meson metadata, and the successful build identity. They have not yet been
rerun end-to-end on a second clean host.

## Qualified environment

- Fedora Linux 44, kernel `7.1.8-200.fc44.x86_64`;
- NVIDIA driver `610.57.04`;
- CUDA toolkit `13.3`, NVCC `13.3.73`;
- Python `3.12.13`;
- GCC/G++ `15.3.1`;
- Rust/Cargo `1.97.1`;
- one RTX PRO 6000 Blackwell 96 GB, SM120.

The relevant installed Python packages are recorded in
[evidence/environment/runtime-stack.txt](evidence/environment/runtime-stack.txt).
CUDA, PyTorch, SGLang, FlashInfer, `sglang-kernel`, the host compiler, NIXL,
and generated JIT caches should be treated as one compatibility unit.

## Source checkout

Clone this repository normally. Do not replace it with current SGLang `main`.
The publication commit adds documentation and recipes, while executable source
must still match the measured runtime commit:

```bash
git diff --exit-code 8e197ed3afc559f29562a2e7de9026f011f5d28f -- python rust
```

## Python environment

Create an isolated Python 3.12 environment. The deployed path was
`/opt/sglang/.venv`; the location is not semantically important.

```bash
uv python install 3.12.13
uv venv --python 3.12.13 .venv
source .venv/bin/activate

export CUDA_HOME=/usr/local/cuda
export CUDACXX="$CUDA_HOME/bin/nvcc"
export CC=/usr/bin/gcc-15
export CXX=/usr/bin/g++-15
export CUDAHOSTCXX=/usr/bin/g++-15
export TORCH_CUDA_ARCH_LIST=12.0

export MAX_JOBS=24
export CMAKE_BUILD_PARALLEL_LEVEL=24
export FLASHINFER_NINJA_JOBS=24
export FLASHINFER_NVCC_THREADS=4
export TORCHINDUCTOR_COMPILE_THREADS=24
```

Install the CUDA 13 dependency set from the exact `python/pyproject.toml` in
this tree, allowing SGLang's CUDA 13 wheel index for pinned native components:

```bash
uv pip install --prerelease=allow \
  --index-strategy unsafe-best-match \
  --extra-index-url https://docs.sglang.ai/whl/cu130/ \
  --no-build-isolation \
  -e python
```

An editable installation is the simplest way to guarantee that imports use the
frozen checkout. For a redistributable local wheel, build from `python/` with
the same environment and install that wheel into the venv. The measured host's
wheel was CPython 3.12, `linux_x86_64`, generated by setuptools 84.0.0.

Verify versions before starting a model:

```bash
python -c 'import importlib.metadata as m; print(m.version("sglang")); print(m.version("torch")); print(m.version("flashinfer-python"))'
nvcc --version
gcc-15 --version
```

## NIXL POSIX build

The qualified NIXL build used commit
`aecbc3846d92c34c7507a58d776e1fda50ff4fba`, release mode, SM120, and only the
POSIX plugin. The following follows the NIXL CUDA 13 source workflow and the
recorded Meson configuration:

```bash
git clone https://github.com/ai-dynamo/nixl.git
cd nixl
git checkout aecbc3846d92c34c7507a58d776e1fda50ff4fba

export CC=/usr/bin/gcc-15
export CXX=/usr/bin/g++-15
export CUDAHOSTCXX=/usr/bin/g++-15

python -m pip install tomlkit
python -m pip install .
./contrib/tomlutil.py --wheel-name nixl-cu13 pyproject.toml
meson setup build-posix \
  --buildtype=release \
  --prefix=/opt/nvidia/nvda_nixl \
  --libdir=lib64 \
  -Denable_plugins=POSIX \
  -Dnixl_cuda_arch_list=120
ninja -C build-posix -j24 install
python -m pip install build-posix/src/bindings/python/nixl-meta/nixl-*-py3-none-any.whl
```

The qualified platform wheel was `nixl-cu13==1.4.0` with SHA-256
`b2d618bc9593bf78120b44f9d573af8807e83716ae8c539b0f1532cc55a55ad8`.
Confirm the POSIX backend and Python binding before serving.

## Model acquisition

Download the exact revisions listed in
[evidence/models/checkpoints.json](evidence/models/checkpoints.json). For
example, with the Hugging Face CLI:

```bash
hf download orcarouter/Qwen3.8-27B-Uncensored-FP8 \
  --revision 9228df5c6c9c509e1019f83b4e085cf643118bac \
  --local-dir /path/to/target
hf download incoai/Qwen3.8-27B-DFlash2 \
  --revision adde41d8fde3a75dc905a7df0bd5088d2a44b5a1 \
  --local-dir /path/to/draft
```

Verify the config, index, and LFS hashes before treating a reproduction as the
same checkpoint pair.

## First start and JIT completion

Use the recipe in [RUN.md](RUN.md). The first start performs CUDA graph capture
and may build JIT kernels. Run several ordinary thinking-enabled warmups before
measuring. Reuse the configured compiler/JIT cache between starts. A clean
machine reproduction is not complete merely because `/health` answers: verify
that DFlash2, target/draft FP8 KV, TRTLLM-MHA/XQA target decode, FlashInfer
draft attention, and CUDA graphs are active in the startup/runtime logs.
